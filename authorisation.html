WHO CAN DO WHAT?

Roles and authorisation

Logging in tells Laravel who you are. Authorisation decides what you are allowed to do.

Different checks answer different questions: validation asks whether submitted information is acceptable; authorisation asks whether this user may perform the action. Both matter.

01 / TWO DIFFERENT CHECKS

Being signed in is not enough.

Authentication

Are you signed in? The auth middleware checks this.

Role-based access

Are you an administrator? Our role:admin middleware checks this.

Record ownership

Did you write this review? Check the review's user_id.

THE MAIN IDEAPermission is checked on the server.

Hiding a button helps the interface, but it does not stop someone typing a protected URL directly.

02 / ROLES AND ROUTES

Only administrators manage books.

An application can store a role such as user or admin on each account. Laravel runs middleware before a protected controller action.

routes/web.php · a simplified example
Route::middleware(['auth', 'role:admin'])->group(function () {
    Route::resource('books', BookController::class)
        ->only(['create', 'store', 'edit', 'update', 'destroy']);
});

auth means logged in. role:admin checks the role. If a signed-in non-admin tries these actions, Laravel returns 403 Forbidden.

The name role here is a middleware alias: a short label registered in bootstrap/app.php for our own middleware class. The class contains the actual role check.

Middleware · the key check
if ($request->user()?->role !== 'admin') {
    abort(403);
}

The check stops non-admin users even if they enter a URL manually. This is an illustrative extract, not the complete middleware file.

03 / OWNERSHIP AND INTERFACE

You can edit your own review, not someone else's.

Roles are not the only kind of permission. A user might be allowed to write reviews but only change reviews they created.

ReviewController.php · record ownership check
if ($review->user_id !== auth()->id()) {
    abort(403);
}

$review->user_id is the review's owner; auth()->id() is the signed-in user. Different IDs mean no permission.

In Blade, the interface can show actions conditionally:

books/index.blade.php · show Add Book to admins
@if (auth()->user()?->role === 'admin')
    <a href="{{ route('books.create') }}">Add Book</a>
@endif

This improves the interface; middleware still provides the real protection.
