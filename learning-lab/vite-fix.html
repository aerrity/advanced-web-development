Docker development environment · Vite and live reloading

Make live styling work with Vite

Vite gives you live frontend updates as you edit Blade, Tailwind and JavaScript. If your app loses its styling when you run npm run dev, use this guide to connect the development server correctly through Docker.

WHY YOU WANT THE VITE DEVELOPMENT SERVER

Live reloading: see your frontend changes immediately

Live reloading means Vite watches your frontend files while you work. Edit a Blade view or change a Tailwind class, save the file, and your browser updates automatically. For many CSS and JavaScript changes, Vite uses Hot Module Replacement (HMR) to update the page without a full refresh.

Try it: with npm run dev running, open your Laravel app, change a heading or a Tailwind colour class in a Blade template, and save. You should see the change in your browser without running npm run build again.

Why this is useful: while you redesign navigation, cards, forms, layouts and other frontend details, you can make a change, see the result straight away, and refine it repeatedly. That makes frontend development much faster.

Remember: npm run dev needs to keep running in your Docker workspace terminal during development. If you stop it, you lose live updates. You can still run npm run build to generate static CSS/JavaScript when needed. Vite is primarily for frontend assets; PHP controller or database changes still run through Laravel as usual.

What you might notice

Pages display with plain browser styling, book covers become very large, cards stack in one column, or changes to CSS and JavaScript do not appear. The Laravel application may still load and work, but its frontend assets aren't reaching your browser correctly.

STEP 1

Open the correct file

In your Laravel project, open src/vite.config.js (or vite.config.js if VS Code is already opened in src). This is the configuration file for the development server.

Replace its contents with the following configuration. It keeps the existing Laravel asset inputs and tells Vite to accept connections from outside its Docker container.

src/vite.config.js · complete file
import { defineConfig } from 'vite';
import laravel from 'laravel-vite-plugin';

export default defineConfig({
    plugins: [
        laravel({
            input: ['resources/css/app.css', 'resources/js/app.js'],
            refresh: true,
        }),
    ],
    server: {
        host: '0.0.0.0',
        port: 5173,
        strictPort: true,
        hmr: {
            host: 'localhost',
            port: 5173,
        },
    },
});

What these settings mean: 0.0.0.0 lets Docker forward connections into Vite; port 5173 is the development-server port; localhost tells the browser where to connect for live updates; and strictPort stops Vite silently picking a different port.

STEP 2

Run Vite from the workspace container

Open your terminal in the project folder containing compose.yaml, then run:

Terminal · project root (the folder containing compose.yaml)
docker compose exec workspace-container npm run dev

Leave this terminal running while you develop. Vite watches your frontend files and serves updated CSS and JavaScript as you work. Open a second terminal for Artisan, Git or other commands.

If you are already inside a terminal session in the workspace container, simply run npm run dev there.

STEP 3

Check that it is working

  1. Leave Vite running and open http://localhost:8080, your Laravel application.
  2. Check the Books index: on desktop, cards should form a grid with correctly sized covers, rather than a long column of oversized images.
  3. Visit http://localhost:5173/@vite/client in your browser. If Vite is reachable, this displays JavaScript text, not a connection error.
  4. Try a small frontend change, such as altering a Tailwind class in a Blade template. The browser should show the updated appearance while Vite is running.
Expected result: the site is styled correctly, and frontend changes can appear without running a new build after every edit.
STEP 4

Understand the two npm commands

npm run dev — while actively developing

Starts a live Vite server. Laravel switches to loading CSS and JavaScript from that server, so the terminal needs to stay running. This is especially useful when adjusting Blade layouts, Tailwind classes or JavaScript.

npm run build — compile static assets

Writes compiled CSS and JavaScript to public/build/. Apache can then serve those files without a running Vite server. Use this when you want a stable build or don't need live updates.

Important: if Vite is running but your browser cannot connect to it, running npm run build alone may not fix the missing styling. Laravel uses the development server while the public/hot marker is present.

When you've finished a development session, stop Vite using Ctrl+C. If you're switching back to static assets, run npm run build. If Vite has stopped but Laravel still tries to load assets from port 5173, check for a stale public/hot file and remove that marker only when Vite is definitely not running.

If it still looks unstyled

Does Docker publish port 5173?
Run docker compose ps and check that the workspace service publishes port 5173 to your computer. If it doesn't, the Compose configuration may need a port mapping for that service. Do not add a second mapping if another service already uses the port.
Does Vite start successfully?
Look for a ready message in the terminal. If Vite reports that port 5173 is in use, stop the other process before trying again.
Do the browser and Docker agree on the address?
The examples assume the Laravel app is at localhost:8080 and the browser runs on the same computer as Docker Desktop. If you use another hostname, remote machine or port, the Vite HMR host and port may need adjusting.
Still requesting old files?
Refresh the browser without cached assets, and inspect the browser's Network tab for failed requests to port 5173.
