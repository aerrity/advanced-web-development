DATA & RELATIONSHIPS

Working with data

A database stores the records. Eloquent lets you work with those records using PHP objects, without writing SQL for each operation.

01 / SEPARATE THE JOBS

Four related ideas, four different purposes.

Migration

Describes a database change: tables, columns and keys.

Model

A PHP class used to query and change database records.

Factory

Defines how to generate realistic sample model data.

Seeder

Chooses which records to insert into a development database.

Terminal
php artisan migrate
php artisan db:seed
php artisan tinker

These commands perform different tasks: update schema, populate records and explore data.

02 / RELATIONSHIPS

Books, authors and reviews are connected.

1 : many
Reviewbelongs to a Book
Bookhas many Authors
many : many
Authorhas many Books
app/Models/Book.php
public function reviews()
{
    return $this->hasMany(Review::class);
}

public function authors()
{
    return $this->belongsToMany(Author::class);
}

Why do we need an author_book table?

A book may have more than one author, and an author may write more than one book. Neither table can store all those links neatly in a single column.

Instead, Laravel uses a pivot table called author_book. Each row connects one book to one author using their IDs.

Here, Book 1 has Authors 3 and 8. Author 3 is also linked to Book 2. These are example IDs, not actual book records.

The belongsToMany() relationship tells Eloquent to use that intermediate table. You can then access a book’s authors with $book->authors rather than manually joining tables.

03 / ASK FOR DATA

Eloquent queries read like PHP.

Tinker
// Count all books in the database.
Book::count();

// Get the first book, including its related authors.
Book::with('authors')->first();

// Find every book whose title contains 'Dune'.
Book::where('title', 'like', '%Dune%')->get();
THE MAIN IDEAThe model is not the table.

A model is PHP code representing and interacting with records. The database table stores the actual data.

?You added a new database column. Should you change a factory or create a migration?Reveal answer

Create a migration to change the database structure. You may then update a factory if the new field should appear in sample records.
