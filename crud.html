COMMON ACTIONS

CRUD: reading and changing data

Most web apps let people create, read, update and delete records. Laravel resource controllers name these common operations consistently.

01 / THE CRUD MAP

Four operations, seven controller methods.

OperationActionsWhat the user experiences
Readindex(), show()Browse all books, open one book
Createcreate(), store()Display a blank form, save its contents
Updateedit(), update()Display a populated form, save changes
Deletedestroy()Remove a record
THE MAIN IDEAForm display and saving are separate steps.

create() shows the form; store() saves it. edit() shows an existing record in a form; update() saves changes.

02 / READ

Show a list, or open one record.

index() loads a collection of books for a listing page. show() displays one specific book. Both are handled by GET requests, so they should not change the database.

BookController.php · simplified read actions
// List books on the index page.
public function index()
{
    $books = Book::all();
    return view('books.index', compact('books'));
}

// Show one book. Laravel resolves $book from the URL.
public function show(Book $book)
{
    return view('books.show', compact('book'));
}

Book::all() returns all books. compact('books') passes the variable to the Blade template. For larger collections, use pagination as in the Learning Lab.

03 / CREATE

Show a blank form, then save a new book.

create() shows the empty form using a GET request. When the user submits it, a POST request goes to store(), which validates the values and creates the new database record.

BookController.php · simplified create actions
// Show an empty form.
public function create()
{
    return view('books.create');
}

// Process the submitted form.
public function store(Request $request)
{
    $data = $request->validate([
        'title' => ['required', 'string'],
    ]);

    Book::create($data);
    return redirect()->route('books.index');
}
VALIDATION IS DIFFERENT FROM AUTHORISATIONIs this data acceptable?

$request->validate() checks the values submitted through a form. For example, required means the field must not be empty, string expects text, and max:255 limits its length. If validation fails, Laravel returns the user to the form with error messages and their previous input.

Validation checks the data. Authorisation checks whether the user is allowed to perform the action. A valid title does not give an ordinary user permission to create books.

books/create.blade.php · form
<form method="POST" action="{{ route('books.store') }}">
    @csrf
    <input name="title" required>
    <button type="submit">Create book</button>
</form>

@csrf adds a hidden security token to the form. When you submit it, Laravel checks that the token matches your session. This helps prevent another website from secretly making your browser submit a form to your application while you are signed in. It does not check whether the input is valid or whether you have permission to create books; those are separate checks.

04 / UPDATE

Load existing values, then save the edits.

edit() shows a form containing the selected book’s current details. update() validates the submission and changes that existing record, instead of inserting a new one.

BookController.php · simplified update actions
// Display the edit form with the existing book.
public function edit(Book $book)
{
    return view('books.edit', compact('book'));
}

// Validate and save the changes.
public function update(Request $request, Book $book)
{
    $data = $request->validate([
        'title' => ['required', 'string'],
    ]);

    $book->update($data);
    return redirect()->route('books.show', $book);
}
books/edit.blade.php · form
<form method="POST" action="{{ route('books.update', $book) }}">
    @csrf
    @method('PUT')
    <input name="title" value="{{ old('title', $book->title) }}">
    <button type="submit">Save changes</button>
</form>

old('title', $book->title) keeps submitted input after a validation error, otherwise it shows the current title. HTML forms don’t directly support PUT, so @method('PUT') tells Laravel which request method to treat it as.

05 / DELETE

Remove the selected record.

destroy() deletes a book identified by its route parameter. A form sends a DELETE request to that action; a normal link should not delete data.

BookController.php · simplified delete action
// Delete a specific book, then go back to the list.
public function destroy(Book $book)
{
    $book->delete();
    return redirect()->route('books.index');
}
books/show.blade.php · delete form
<form method="POST" action="{{ route('books.destroy', $book) }}">
    @csrf
    @method('DELETE')
    <button type="submit">Delete book</button>
</form>

In a real app, only authorised users should be able to delete books. You should also consider how related reviews and other records are handled.
