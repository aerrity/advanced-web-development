THE BIG PICTURE

MVC and the request lifecycle

When someone visits a URL, Laravel connects several small pieces of code to produce the result. MVC is a way of separating their responsibilities.

01 / ONE REQUEST

What happens when you visit /books?

01BrowserGET /books
02RouteFinds index()
03ControllerCoordinates the work
04ModelFetches books
05ViewBuilds HTML

The controller gives data to the view, and Laravel sends the finished HTML back to the browser. Middleware may check access before the controller runs.

02 / FOUR PIECES

Look at the same page in four places.

routes/web.php
Route::get('/books', [BookController::class, 'index'])
    ->name('books.index');
app/Http/Controllers/BookController.php
public function index()
{
    $books = Book::all();

    return view('books.index', compact('books'));
}
app/Models/Book.php
class Book extends Model
{
    // Eloquent represents a book record.
}
resources/views/books/index.blade.php
@foreach ($books as $book)
    <p>{{ $book->title }}</p>
@endforeach
THE MAIN IDEARoute → Controller → Model → View

The route chooses the controller action. The controller asks the model for data and returns a view. The view presents it. Real applications can take more steps.

03 / HTTP REQUESTS

The browser tells Laravel what it wants.

MethodTypical meaningBook Reviews example
GETRead a pageShow the catalogue
POSTCreate somethingSave a new book
PATCHChange somethingUpdate a book
DELETERemove somethingDelete a book
?A user submits a form to update a book. Which part receives the request first: the route, controller or model?Reveal answer

Laravel matches the route first. The route then directs the request to the appropriate controller action (after relevant middleware).
