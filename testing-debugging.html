QUALITY & CONFIDENCE

Testing and debugging

Automated tests give you a repeatable way to check behaviour. Debugging helps you explain and fix problems when the behaviour is wrong.

01 / TWO TYPES OF TEST

What are you checking?

Model / unit-style test

Check a model rule, a relationship or a small piece of logic.

Feature test

Send a simulated HTTP request and check the response, data or permissions.

Terminal
php artisan test
php artisan test --filter=BookTest

02 / A FEATURE TEST

Arrange, act, assert.

tests/Feature/BookTest.php · illustrative test
public function test_books_page_requires_login(): void
{
    // Act
    $response = $this->get(route('books.index'));

    // Assert
    $response->assertRedirect(route('login'));
}

This example assumes the catalogue is behind auth middleware, as in the guided app.

Arrange

Create the records or users needed for the test.

Act

Make the request or call the method.

Assert

Check the result matches what you expected.

03 / WHEN IT FAILS

Read the error before changing code.

SymptomFirst thing to check
View [reviews.create] not foundIs the Blade file in resources/views/reviews/create.blade.php?
Class ... Request does not existDoes the controller import Illuminate\Http\Request?
404 on a routeWhat does php artisan route:list show?
Test fails unexpectedlyWhat did the test expect? What actually happened?
THE MAIN IDEAA passing test is evidence, not a guarantee.

Good tests cover meaningful cases, including errors and unauthorised users.
